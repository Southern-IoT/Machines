## `del` shell function — the auto-logging helper

The following shell function logs every deletion to this file **before** running
`rm`. Source it once into your shell session, or add it to `~/.bashrc` /
`~/.zshrc` for persistence.

```bash
# Add to ~/.bashrc, ~/.zshrc, or paste into a fresh shell session.
del() {
  local reason="${1:-no reason given}"
  shift || true
  if [ "$#" -eq 0 ]; then
    echo "Usage: del <reason> <file> [file...]"
    echo "  e.g.: del 'moved to new tool' src/old.txt"
    return 1
  fi
  local logfile="deleted_files.md"
  if [ ! -f "$logfile" ]; then
    echo "ERROR: $logfile not found in $(pwd)" >&2
    return 1
  fi
  local ts
  ts="$(date -Iseconds)"
  {
    echo
    echo "### \`$*\` — deleted $(date '+%Y-%m-%d %H:%M:%S %Z')"
    echo
    echo "**Reason:** $reason"
    echo
    echo "| Path | Action |"
    echo "|---|---|"
    for f in "$@"; do
      local size=""
      if [ -e "$f" ]; then
        size=$(du -sh "$f" 2>/dev/null | cut -f1)
        echo "| \`$f\` | deleted (${size:-unknown size}) |"
      else
        echo "| \`$f\` | (path did not exist at time of deletion) |"
      fi
    done
  } >> "$logfile"
  echo "Appended deletion entry to $logfile"
  rm -rf "$@"
  echo "Removed: $*"
}
```

**Usage examples:**

```bash
# Single file with reason
del "old planning file" .brand-list.txt

# Multiple files, same reason
del "gitignored build cache, will rebuild on next build" .astro/ tina/__generated__/ dist/

# Whole directory
del "test fixtures, not referenced by code" downloads/

# No reason — function will still work but logs "no reason given"
del SOMEFILE
```

After running `del`, the entry appears at the bottom of `deleted_files.md`. You
can verify with `tail deleted_files.md` or `git diff deleted_files.md`.

## Workflow for future deletions (recommended)

1. **Before deleting** any file or directory, ask: "is this file (a) tracked in git, (b) referenced from any code, (c) referenced from any documentation, (d) part of an active workflow?" If the answer to all four is "no", it's a candidate for deletion.
2. **Run `del`** with a short reason. The function logs to this file and executes `rm -rf`.
3. **For tracked files**, follow the deletion with a normal `git add -A && git commit -m "chore: remove <file> — <reason>"`. Git's own diff captures the *what*; this log captures the *why*.
4. **For gitignored build artifacts** (`.astro/`, `dist/`, `tina/__generated__/`, `node_modules/`), no commit is needed — they're never tracked. This log entry is the only record of their removal.
5. **For directories**, prefer `del dir/` over `del dir/file` — it captures the whole subtree in one entry.

If you ever delete something via plain `rm` (not the `del` function), backfill
the entry manually with the same format:

```bash
cat >> deleted_files.md <<'EOF'

### `path/to/file` — deleted 2026-07-23 14:32:01 +06:00

**Reason:** backfilled entry (not run through `del` function).

| Path | Action |
|---|---|
| `path/to/file` | deleted (4.2 KB) |
EOF
```
