# Southern Machines — Complete Project Blueprint

This document explains everything needed to replicate this project from scratch. Written so another AI or developer can build a similar static machine database website with zero confusion.

---

## What This Project Is

A **static factory machine database website** built with:
- **Astro 6** — static site generator
- **TinaCMS** — Git-based headless CMS (content stored as JSON files in the repo)
- **Tailwind CSS 4** — utility-first styling
- **GitHub Pages** — free static hosting
- **GitHub Actions** — auto-deploy on every push to `main`

The site has two pages:
1. **Homepage** (`/`) — machine card grid with search and filter
2. **Machine detail** (`/machines/[slug]`) — full technical page per machine

## Step 2 — astro.config.mjs

**CRITICAL:** The `site` and `base` must match your GitHub Pages URL exactly.

```js
// astro.config.mjs
import { defineConfig } from "astro/config";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  site: "https://YOUR-GITHUB-USERNAME.github.io",
  base: "/YOUR-REPO-NAME/",   // e.g. "/Machines/"
  output: "static",
  vite: {
    plugins: [tailwindcss()],
  },
});
```

**Why this matters:**
- Without `base`, all internal links and image paths break on GitHub Pages
- The `base` must have a leading AND trailing slash: `/Machines/`
- If your repo is at the root (e.g. `username.github.io`), use `base: "/"`

---

## Step 3 — Image Path Fix (CRITICAL for GitHub Pages)

Because of the `base` path, images stored in `public/uploads/` are served at `/Machines/uploads/` on GitHub Pages, not `/uploads/`.

**Fix in every component that renders images:**

```astro
---
const base = import.meta.env.BASE_URL.replace(/\/$/, "");
const imageSrc = image?.startsWith("/") ? `${base}${image}` : image;
---
<img src={imageSrc} alt={title} />
```

**Also fix internal links:**
```astro
<!-- Machine card link -->
const base = import.meta.env.BASE_URL.replace(/\/$/, "");
<a href={`${base}/machines/${slug}/`}>
```

```astro
<!-- Back to directory link -->
<a href="/YOUR-REPO-NAME/">Back to Directory</a>
```

**Rule:** Any hardcoded path starting with `/` that points to a page or image must include the base path prefix.

## Step 5 — Content Schema (JSON files)

Each machine is a JSON file in `src/content/machines/`. The filename becomes the URL slug.

**Example: `src/content/machines/juki-lk-1900bn.json`**
→ URL: `https://username.github.io/Machines/machines/juki-lk-1900bn/`

    "purpose": "What this machine does and why it exists.",

## Step 6 — Dynamic Page Route

**src/pages/machines/[slug].astro** reads JSON files at build time:

```astro
---
import fs from "node:fs";
import path from "node:path";

export function getStaticPaths() {
  const machinesDir = path.join(process.cwd(), "src/content/machines");
  const files = fs.readdirSync(machinesDir).filter(f => f.endsWith(".json"));
  return files.map(file => {
    const raw = fs.readFileSync(path.join(machinesDir, file), "utf-8");
    const data = JSON.parse(raw);
    return {
      params: { slug: file.replace(".json", "") },
      props: { machine: data },
    };
  });
}

const { machine } = Astro.props;
const base = import.meta.env.BASE_URL.replace(/\/$/, "");
const machineImageSrc = machine.machineImage?.startsWith("/")
  ? `${base}${machine.machineImage}`
  : machine.machineImage;
---
```

## Step 8 — Search and Filter (Client-Side)

The search is in the Navbar. Machine data is serialized into the page at build time and used by client-side JavaScript.

**In Navbar.astro:**
```astro
---
const machinesJson = JSON.stringify(machines);
---
<script define:vars={{ machinesJson }}>
  const allMachines = JSON.parse(machinesJson);
  // filter logic here
</script>
```

**Autocomplete dropdown** uses `position: fixed` with JavaScript positioning to escape `overflow: hidden` parent containers:
```js
function positionDropdown() {
  const rect = inputElement.getBoundingClientRect();
  dropdown.style.top = (rect.bottom + 4) + "px";
  dropdown.style.left = rect.left + "px";
  dropdown.style.width = rect.width + "px";
}
```

**Grid filtering** — each machine card has `data-*` attributes:
```html
<a data-brand="juki" data-category="sewing machine" data-search="full searchable text">
```

Filter function:
```js
function applyFilters() {
  const query = searchInput.value.toLowerCase().trim();
  const brand = brandFilter.value.toLowerCase();
  const category = categoryFilter.value.toLowerCase();
  
  cards.forEach(card => {
    const show = (!query || card.dataset.search.includes(query))
      && (!brand || card.dataset.brand === brand)
      && (!category || card.dataset.category === category);
    card.style.display = show ? "flex" : "none";
  });
  
  // IMPORTANT: Always keep grid display as "grid", never hide it
  grid.style.display = "grid";
}
```

**Common mistake:** Setting `grid.style.display = "none"` when no results — this breaks the grid layout when results return. Instead, keep the grid as `display: grid` always and show a separate "no results" div.

## Step 9 — TinaCMS Setup

### 9.1 — tina/config.ts

```typescript
import { defineConfig } from "tinacms";

export default defineConfig({
  branch: process.env.TINA_BRANCH || process.env.GITHUB_BRANCH || "main",
  clientId: process.env.TINA_PUBLIC_CLIENT_ID || "",
  token: process.env.TINA_TOKEN || "",

  build: {
    outputFolder: "admin",      // admin panel goes to public/admin/
    publicFolder: "public",
    basePath: "YOUR-REPO-NAME", // CRITICAL: must match astro base (without slashes)
    // e.g. basePath: "Machines"
  },

  media: {
    tina: {
      mediaRoot: "uploads",
      publicFolder: "public",
    },
  },

  schema: {
    collections: [
      {
        name: "machine",
        label: "Machines",
        path: "src/content/machines",
        format: "json",
        // ... fields
      }
    ]
  }
});
```

**CRITICAL — `basePath` in tina/config.ts:**
- Must match the repo name (without slashes)
- If astro `base` is `/Machines/`, then tina `basePath` is `"Machines"`
- Without this, the admin panel at `/Machines/admin/` fails to load its assets

## Step 10 — GitHub Actions Deployment

### 10.1 — .github/workflows/deploy.yml

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    environment:
      name: github-pages    # CRITICAL: must reference this environment to access environment secrets
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build site
        run: npx tinacms build && npm run build
        env:
          TINA_PUBLIC_CLIENT_ID: ${{ secrets.TINA_PUBLIC_CLIENT_ID }}
          TINA_TOKEN: ${{ secrets.TINA_TOKEN }}

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: dist/

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

**Why `environment: name: github-pages` on the build job:**
- GitHub Secrets can be stored as "environment secrets" under the `github-pages` environment
- Without referencing the environment in the build job, those secrets are not accessible
- Both the build job AND the deploy job must reference `github-pages` environment

### 10.2 — GitHub Repository Settings

1. Go to repo → **Settings → Pages**
2. Source: **GitHub Actions** (not "Deploy from a branch")
3. Save

### 10.3 — GitHub Secrets

Go to repo → **Settings → Secrets and variables → Actions → New repository secret**:
- `TINA_PUBLIC_CLIENT_ID` = your TinaCloud Client ID
- `TINA_TOKEN` = your TinaCloud Token

Also add them as **Environment secrets** under Settings → Environments → github-pages → Add secret (both locations work, repository secrets are simpler).

## Step 11 — Sequence Flow Component (SVG Flowchart)

The sequence flow renders as a vertical flowchart with SVG arrows and a decision diamond at the end.

**Detection logic** — last step is treated as a decision node if its title contains "check", "quality", or "inspect":
```astro
const isDecision = (step) => /check|quality|inspect/i.test(step.stepTitle);
const hasDecision = isDecision(steps[steps.length - 1]);
const mainSteps = hasDecision ? steps.slice(0, -1) : steps;
```

**Decision diamond** uses SVG `<polygon>` for pixel-perfect rendering:
```html
<svg width="200" height="110" viewBox="0 0 200 110">
  <polygon points="100,6 194,55 100,104 6,55"
    fill="#fff8e1" stroke="#ff9900" stroke-width="2"/>
  <text x="100" y="55" text-anchor="middle">Quality Check</text>
</svg>
```

**Yes/No branches** use SVG lines and arrows for precise connections — no CSS positioning issues.

## Step 12 — Parts Table (Mechanical / Electronic Split)

Parts are split into two tables based on the `section` field in JSON:

```astro
const mechanical = parts.filter(p => !p.section || p.section === "mechanical");
const electronic = parts.filter(p => p.section === "electronic");
const hasSections = electronic.length > 0;
```

If no parts have `section: "electronic"`, a single table is shown. This makes it backward-compatible with machines that don't have the section field.

## Step 13 — Sidebar Scroll-Spy

The sidebar uses scroll position (not IntersectionObserver) for reliable active section highlighting:

```js
function getActiveSection() {
  const scrollY = window.scrollY + 80; // offset for sticky navbar height
  let current = sections[0]?.id || "";
  for (const section of sections) {
    if (section.offsetTop <= scrollY) {
      current = section.id;
    }
  }
  return current;
}

window.addEventListener("scroll", () => {
  setActive(getActiveSection());
}, { passive: true });
```

**Why not IntersectionObserver:** It's unreliable when sections are short or when scrolling fast. The scroll position approach always highlights the correct section.

## Common Mistakes and Fixes

### 1. Images not loading on GitHub Pages
**Cause:** Image paths like `/uploads/image.jpg` don't include the base path.
**Fix:** Prepend `import.meta.env.BASE_URL` to all image paths that start with `/`.

### 2. Admin panel shows "Failed loading TinaCMS assets"
**Cause:** `basePath` missing or wrong in `tina/config.ts`.
**Fix:** Set `build.basePath: "YOUR-REPO-NAME"` (no slashes, just the repo name).

### 3. Admin panel shows "TinaCloud config missing for domain"
**Cause:** Your GitHub Pages domain not added to TinaCloud project.
**Fix:** Go to app.tina.io → Project → Configuration → Site URLs → add `https://username.github.io`.

### 4. GitHub Actions build fails with "TINA_PUBLIC_CLIENT_ID not found"
**Cause:** Secrets added as environment secrets but build job doesn't reference the environment.
**Fix:** Add `environment: name: github-pages` to the build job in deploy.yml.

### 5. Search dropdown hidden behind other elements
**Cause:** Dropdown is inside an `overflow: hidden` container.
**Fix:** Render the dropdown outside all containers using `position: fixed` and JavaScript positioning with `getBoundingClientRect()`.

### 6. Grid collapses to single column when filtering
**Cause:** Setting `grid.style.display = "none"` when no results, then restoring to `""` (empty string defaults to block, not grid).
**Fix:** Never hide the grid. Keep `grid.style.display = "grid"` always. Show/hide a separate "no results" div instead.

### 7. 404 on machine detail pages
**Cause:** Machine card links use `/machines/slug/` without the base path.
**Fix:** Use `${base}/machines/${slug}/` where `base = import.meta.env.BASE_URL.replace(/\/$/, "")`.

### 8. Push rejected after GitHub Actions auto-commit
**Cause:** TinaCMS or GitHub Actions committed to the repo while you were working locally.
**Fix:** `git pull --rebase origin main` then `git push`.

## Adding a New Machine

1. Create `src/content/machines/machine-slug.json` following the schema in Step 5
2. Add `"section": "mechanical"` or `"section": "electronic"` to each part in `partsList`
3. If the last `sequenceFlow` step contains "check" or "quality", it auto-renders as a decision diamond
4. Commit and push — site rebuilds automatically
5. Or use the TinaCMS admin at `/REPO-NAME/admin/` to add via UI
